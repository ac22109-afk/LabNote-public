# LabNote — 公開用ポートフォリオ版

研究室内向けに開発した研究記録アプリから、公開用に構成・設定・説明を整理したデモ版です。
本番版の履歴を再現するものではありません。実際の研究記録、接続設定、認証情報、配布物は含めません。
元repoとは独立した公開用スナップショットであり、元のGit履歴や内部運用文書を含みません。

## 解決したい課題

試料・処理・測定・添付を関連付け、複数人が検索・比較できるようにするアプリです。
Web/DBサーバーを共有ストレージに追加しない環境を想定し、各PCのデスクトップアプリと共有ファイルで構成します。
原本は追記型JSONと添付、SQLiteは各PCの検索索引です。

## 試す（Windows / Python 3.12）

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python -m fileclient
```

標準起動はローカルデモです。「仮データ」の追加操作で架空の試料・測定・処理を作成できます。
データは `var/file-client-demo/`、設定等は本番版と分離したユーザー領域 `LabNotePortfolio` に保存します。
初期画面の「自分の試料」に出ないときは「全員の試料」に切り替えてください。
実データを読み込まず、試す場合も架空のCSV・画像を使ってください。
OSのTkinterと所定のフォントが必要です。フォント本体は同梱しません。

## 設定

接続先・データ識別子をソースや文書に直書きしません。
必要な場合だけ `labnote-deployment.example.json` をGit管理外の `labnote-deployment.json` にコピーし、
架空の保存先・検証用データIDに設定します。見本は実在する保存先やデータを表しません。
通常のデモ起動では接続設定を使いません。`--store` は既存の検証用ストアを開く明示操作です。
パスワード・鍵をこの設定に含めず、共有先の認証はOS側に委ねます。

## 設計と制約

- オフラインの新規登録をPC内に保持し、接続後に送信する。
- 訂正・削除・復元は改訂として残し、添付のサイズとハッシュを検証する。
- 単位の整合を確認した比較グラフ、CSV/Excel取り込みを提供する。
- 登録者IDは自己申告であり、本人認証・厳密なアクセス制御ではない。
- 競合を自動解決しない。共有ストレージでの複数実機検証とMac検証は、この公開版では未実施。
- 本番の配布・署名・自動更新はこのデモに含めない。

## 公開版の範囲

現行の `fileclient/` と回帰テストを引き継ぎ、旧Django/Web実装、Docker設定、
旧要件書・内部運用文書・過去の検証記録、本番設定、個人テンプレートの未接続実装を除外しました。
例示IDを架空値へ置換し、設定保存先を本番版から分離しました。
これは公開版作成時の整理であり、元の開発当初から同じ構成だったという説明ではありません。

## 検証

```powershell
.venv/Scripts/python check_public.py
.venv/Scripts/python -m unittest discover -s tests -p "test*.py" -q
.venv/Scripts/python -m unittest discover -s fileclient -t . -p "test*.py" -q
```

`check_public.py` は混入しやすいファイル・パターンを検出する補助検査です。
権利の確認や、未知の秘密値が一切ないことの証明にはなりません。
検証結果と残課題は `PUBLICATION_REVIEW.md` を参照してください。

## 開発と保護設定

Git管理外の設定は `.gitignore` で除外し、コミット前チェックとCIでも混入を検査します。
`git config core.hooksPath .githooks` でローカルフックを有効にできます。
GitHub側ではSecret scanning / Push protectionとmainのPR・CI保護を使います。
フォント本体は配布せず、OSに導入済みのものを使います。
元実装と公開版の整理にはAI支援を使っています。独立レビューや実NASでの運用検証を完了したという説明ではありません。
本コードのライセンスは未設定です。依存ライブラリにはそれぞれのライセンスが適用されます。
